# Writing content for UnoffIChO

All content is data, kept apart from the UI. You can add a page, reagent, formula or question without touching a component.

| Content | Where | Format | Picked up |
| --- | --- | --- | --- |
| Book pages | `src/data/book/<chapter>/<id>.mdx` | MDX with YAML frontmatter | automatically (any `.mdx` in a chapter folder) |
| Book outline | `src/data/book/outline.ts` | TS | chapter titles and section order |
| Reagents | `src/data/reagents/*.json` | JSON array | automatically (any `.json` in the folder) |
| "Will it react?" items | `src/data/react-items.json` | JSON array | automatically |
| Formulas | `src/engine/formulas/*.ts` | TS | add to a topic file's array; a new file must also be listed in `formulas/index.ts` |
| Questions (feed) | `src/data/templates/*.ts` | TS | add to a topic file's array; a new file must also be spread into `CALC_TEMPLATES` in `templates/index.ts` |
| Multi-step problems | `src/data/templates/problems.ts` | TS | automatically (exported list) |

Formulas and questions are TypeScript because they contain functions (residuals, constraints). Everything else is plain data.

## Rules for every item

- **Original writing only.** Explain in your own words. Do not copy or closely paraphrase a textbook.
- **`reviewed: false` on everything new.** The app shows "unreviewed" quietly beside such items. Mark items reviewed from the `/review` page (see below).
- **Unsure? Say so.** In data files, add a note to `todoVerify` (a list of strings). In TS, you can also leave a `// TODO(verify): …` comment. Accuracy matters more than volume, so never guess a value.
- **Ids are lowercase kebab-case** (`dibal-h`, `calc-arrhenius-ea`) and must never change once published. Progress and flags are stored against them.

## Checking your work

```bash
npm test
```

The tests validate every data file against its schema. They also check that:

- every SMILES string parses
- every reagent and formula a page links to exists
- every formula's worked example solves and round-trips
- every question template generates instances whose answer matches its reference solution
- every book page renders without a KaTeX error

`npm run dev` and the dev-only **`/debug`** page let you try any formula by hand.

## Reviewing content: `/review`

With `npm run dev` running, open `/review` (for example <http://localhost:5173/review>). It lists every item with `reviewed: false`, with its `todoVerify` notes and anything you have flagged as wrong on this device. Filter by kind, search, or show only items with a TODO.

**Mark reviewed** rewrites `reviewed: false` to `reviewed: true` in the item's own source file, leaving everything else unchanged. Vite reloads the content, and you commit the change like any other edit.

The four weak acid/base formulas (`weak-acid-approx`, `weak-acid-exact`, `weak-base-approx`, `weak-base-exact`) are generated by one function in `formulas/equilibrium.ts`. Set their flag by hand there. **Export review state** downloads what you marked plus what remains, as a fallback record.

The page and its write-back endpoint exist only in the dev server. Neither is in the production build.

## Book page

One file per page, about two minutes of reading on a phone. Frontmatter holds the metadata; the body is Markdown plus a few components.

| Field | Notes |
| --- | --- |
| `id` | kebab-case, unique across the book |
| `chapter` | `physical`, `inorganic`, `organic` or `analytical`; must match the folder |
| `section` | a section id from `outline.ts` |
| `order` | position within the section |
| `title` | |
| `minutes` | reading time, default 2 |
| `related.reagents` / `related.formulas` | ids shown as chips under the page |
| `quickChecks` | 2–3 for a written page (none for a stub). `mcq`: `prompt`, `options` (2–5), `answer` (0-based index), `explanation`. `reveal`: `prompt`, `answer`. Inline `$…$` maths works in all of these strings. |
| `stub` / `outline` | an outline page: `stub: true` plus a list of what it will cover, and no body |
| `reviewed`, `todoVerify` | as above |

What the body can contain:

| Write | Renders as |
| --- | --- |
| `$…$`, `$$…$$` | KaTeX maths, inline or on its own line |
| `\| a \| b \|` tables | tables (GitHub style) |
| `<Smiles smiles="CC(=O)C" label="Acetone" />` | a skeletal structure |
| `<Scheme from="…" to="…" reagent="nabh4" under="MeOH, 0 °C" fromLabel="…" toLabel="…" />` | reactant → arrow → product (`over="…"` instead of `reagent` for free text) |
| `<Callout type="trap">…</Callout>` | a box; `type` is `trap` (Common trap), `tip` (Olympiad tip) or `note` |
| `<R id="dibal-h" />` or `<R id="dibal-h">DIBAL</R>` | a link that opens the reagent card |
| `<F id="nernst" />` | a link that opens the formula |

In MDX, `{` and `<` in ordinary text start code. Keep them inside maths, or write "less than" in words. Put subscripts in maths (`$e_g$`), not as `e_g` in text. The tests catch stray underscores.

```mdx
---
id: buffers-henderson-hasselbalch
chapter: analytical
section: buffers
order: 1
title: Buffers and the Henderson–Hasselbalch equation
minutes: 3
related:
  formulas: [henderson-hasselbalch, ph]
quickChecks:
  - id: ammonia-buffer
    type: mcq
    prompt: "0.20 mol NH₄Cl and 0.10 mol NH₃, $\\mathrm{p}K_\\mathrm{a} = 9.25$. What is the pH?"
    options: ["8.95", "9.25", "9.55", "4.75"]
    answer: 0
    explanation: "$\\mathrm{pH} = 9.25 + \\log_{10}(0.10/0.20) = 8.95$."
  - id: half-eq
    type: reveal
    prompt: "What is the pH at the half-equivalence point of a weak acid titration?"
    answer: "pH = pKₐ, because [HA] = [A⁻] there."
reviewed: false
---

A buffer holds the pH roughly steady when small amounts of acid or base are added.

$$
\mathrm{pH} = \mathrm{p}K_\mathrm{a} + \log_{10}\frac{[\mathrm{A^-}]}{[\mathrm{HA}]}
$$

This is the <F id="henderson-hasselbalch" />.

<Callout type="trap">
Do the stoichiometry first, then use the equation.
</Callout>
```

Inside double-quoted YAML strings, backslashes are doubled (`\\mathrm`). In the MDX body they are single.

## Reagent

| Field | Notes |
| --- | --- |
| `id`, `name`, `aliases`, `formula` | `formula` may use Unicode sub/superscripts |
| `smiles` | optional; only where a drawing helps (organic reagents) |
| `roles` | from `oxidant`, `reductant`, `bronsted-acid`, `bronsted-base`, `lewis-acid`, `lewis-base`, `none` |
| `primaryRole` | one of `roles`; worth full marks in Fast mode |
| `alsoAccept` | defensible extra roles: neither rewarded nor penalised |
| `context` | when the role depends on conditions (H₂O₂, SO₂, …) |
| `strength` | optional `pKaH`, `pKa`, `E0` (V), `note` |
| `typicalUses`, `chemoselectivity`, `pitfalls` | non-empty lists; chemoselectivity says what it does **and does not** do |
| `topic` | e.g. `organic/reduction` |

```json
{
  "id": "nabh4",
  "name": "Sodium borohydride",
  "aliases": ["NaBH4"],
  "formula": "NaBH₄",
  "roles": ["reductant"],
  "primaryRole": "reductant",
  "alsoAccept": ["lewis-base"],
  "typicalUses": ["Reduces aldehydes and ketones to alcohols, usually in MeOH or EtOH at 0 °C to room temperature"],
  "chemoselectivity": [
    "Reduces aldehydes, ketones and acyl chlorides",
    "Does not reduce esters, amides, carboxylic acids or nitriles under normal conditions"
  ],
  "pitfalls": ["It delivers H⁻ to carbon; it is not used as a base"],
  "topic": "organic/reduction",
  "reviewed": false
}
```

## Formula

A formula is a relation between variables with dimensions. The engine can solve it for any variable marked solvable.

| Field | Notes |
| --- | --- |
| `id`, `name`, `topic` | `topic` is `thermo`, `kinetics`, `equilibrium`, `electro` or `other` |
| `latex` | main display form |
| `vars` | built with the helpers in `formulas/vars.ts` (`temp`, `conc`, `molarEnergy`, …); each has a symbol, label, LaTeX, dimension and default unit |
| `relation` | `(v) => [lhs, rhs]` in **SI values**; return `NaN` outside the domain |
| `rearranged` | the LaTeX shown when solving for each variable |
| `bracket`, `constraint`, `warnings` | optional: a search interval, physical validity checks, approximation warnings |
| `examples` | worked values in display units, each with exactly one solvable variable left out. Tests solve for it, then round-trip every other variable. |

```ts
defineFormula({
  id: 'ph',
  name: 'pH',
  topic: 'equilibrium',
  latex: '\\mathrm{pH} = -\\log_{10}\\dfrac{[\\mathrm{H^+}]}{c^\\circ}',
  vars: [pVar('pH', 'pH', '\\mathrm{pH}', 'pH'), conc('H', '[H⁺]', '[\\mathrm{H^+}]', 'Hydrogen ion concentration')],
  relation: (v) => [v.pH!, -log10(v.H! / C_STD)],
  rearranged: {
    pH: '\\mathrm{pH} = -\\log_{10}[\\mathrm{H^+}]',
    H: '[\\mathrm{H^+}] = 10^{-\\mathrm{pH}}',
  },
  examples: [{ H: 3.2e-4 }],
  reviewed: false,
}),
```

## Question template

A template draws random but realistic parameters and shows them as **givens**, rounded as displayed. It computes the answer by running a **reference graph** on those rounded givens, so the expected answer always matches the numbers on screen.

| Field | Notes |
| --- | --- |
| `params` | per parameter: `unit`, `min`/`max` (or `choices`), `log` for log-uniform, `sig` or `decimals`, optional `displayUnits` |
| `setup` | optional hidden graph that derives consistent data from the params |
| `given` | `{ key, label, from }`, where `from` is `p.<param>` or `n.<setup node>`; optional display `unit` / `sig` |
| `reference` | the solution as a graph of steps (see below); the student's route is compared with it by value |
| `answer` | `{ node, label, unit }` |
| `tolerance` | relative (default 0.01) or `{ abs: 0.02 }`, e.g. for pH |
| `misconceptions` | wrong-route graphs with a message, shown when the student's answer matches one |
| `wordings` | question text variants; `{key}` is replaced by the formatted given |
| `approachText` | number-free summary for Approach mode |
| `constraint` | optional `(v) => boolean` on SI values to reject unrealistic instances |
| `difficulty` | 1–3; Exam mode uses 2 and 3 |
| `explanation` | shown after answering |

Graph steps reference values by prefix: `g.` a given, `p.` a param (setup only), `n.` an earlier node, `c.` a constant (`c.R`, `c.F`, …), `#` a literal number (`'#2'`). A step is either a formula, `{ id, formula, solveFor, inputs: { var: ref } }`, or an operation, `{ id, op, inputs }`. The operations are `add`, `sub`, `mul`, `div`, `ln`, `log10`, `exp`, `pow10`, `pow` (with `exponent`), `scale` (with `coef`), `sum` (with `coefs`) and `convert` (with `unit`). An optional `label` names the step's result in Approach mode.

```ts
{
  id: 'calc-second-order-half-life',
  topic: 'kinetics',
  title: 'Second-order half-life',
  difficulty: 1,
  params: {
    k: { unit: 'dm3/(mol s)', min: 1e-3, max: 10, log: true, sig: 2 },
    A0: { unit: 'mol/dm3', min: 0.01, max: 1, sig: 2 },
  },
  given: [
    { key: 'k', label: 'k', from: 'p.k' },
    { key: 'A0', label: '[A]₀', from: 'p.A0' },
  ],
  reference: [{ id: 'thalf', formula: 'half-life-second', solveFor: 'thalf', inputs: { k: 'g.k', A0: 'g.A0' } }],
  answer: { node: 'thalf', label: 't½', unit: 's' },
  misconceptions: [
    {
      reference: [
        { id: 'kk', op: 'mul', inputs: ['g.k', 'g.A0'] },
        { id: 'thalf', op: 'div', inputs: ['#0.6931471805599453', 'n.kk'] },
      ],
      answer: 'thalf',
      message: 'ln 2 belongs to the first-order half-life. For second order, t½ = 1/(k[A]₀).',
    },
  ],
  wordings: ['A second-order reaction (rate = k[A]²) has k = {k}. What is the first half-life when [A]₀ = {A0}?'],
  explanation: 't½ = 1/(k[A]₀). Unlike first order, it depends on the starting concentration.',
  reviewed: false,
},
```

## Multi-step problem

A multi-step problem is the same type, a question template, written by hand at olympiad length (4–8 steps), with `difficulty: 3` and an `approachText`. It lives in `problems.ts`.

```ts
{
  id: 'ms-lindemann-pressure',
  topic: 'kinetics',
  title: 'Lindemann mechanism at a given pressure',
  difficulty: 3,
  params: {
    k1: { unit: 'dm3/(mol s)', min: 1e5, max: 1e8, log: true, sig: 2 },
    km1: { unit: 'dm3/(mol s)', min: 1e9, max: 1e10, log: true, sig: 2 },
    k2: { unit: '1/s', min: 1e4, max: 1e8, log: true, sig: 2 },
    p: { unit: 'kPa', min: 0.1, max: 100, log: true, sig: 2 },
    T: { unit: 'K', min: 300, max: 800, decimals: 0 },
  },
  given: [
    { key: 'k1', label: 'k₁', from: 'p.k1' },
    { key: 'km1', label: 'k₋₁', from: 'p.km1' },
    { key: 'k2', label: 'k₂', from: 'p.k2' },
    { key: 'p', label: 'p', from: 'p.p' },
    { key: 'T', label: 'T', from: 'p.T' },
  ],
  reference: [
    { id: 'RT', label: 'RT', op: 'mul', inputs: ['c.R', 'g.T'] },
    { id: 'M', label: '[M]', op: 'div', inputs: ['g.p', 'n.RT'] },
    { id: 'kuni', formula: 'lindemann', solveFor: 'kuni', inputs: { k1: 'g.k1', km1: 'g.km1', k2: 'g.k2', M: 'n.M' } },
    { id: 'thalf', formula: 'half-life-first', solveFor: 'thalf', inputs: { k: 'n.kuni' } },
  ],
  answer: { node: 'thalf', label: 't½', unit: 's' },
  wordings: ['A gas-phase isomerisation follows the Lindemann mechanism with k₁ = {k1}, k₋₁ = {km1} and k₂ = {k2}. The total pressure is {p} at {T}. Treating the gas as ideal, find the half-life.'],
  approachText: 'Lindemann mechanism with rate constants known; the gas pressure and temperature are given. Find the half-life.',
  explanation: '[M] = p/RT. Then k_uni = k₁k₂[M]/(k₋₁[M] + k₂), which is first order in A, so t½ = ln 2/k_uni.',
  reviewed: false,
},
```

## Progress data

Progress lives only on the device, in IndexedDB, and can be exported and imported as JSON from the Progress screen. Every answer is stored against a namespaced item id: `calc:<template>`, `reagent:<id>`, `react:<id>` or `book:<page>:<check>`. Each answer also updates that item's SM-2 review schedule:

- intervals of 1 day, then 6 days, then interval × ease
- a score below 50% resets the item and brings it back 10 minutes later
- meeting an item again before it is due does not lengthen its interval
